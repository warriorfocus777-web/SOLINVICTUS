## Headline finding — do not wire this engine into the live pages yet

Every Cadre 509 cell below shows an engine-computed originator count higher than the desk's own `orig`/`orig_names`, and every one of those pushes the gate to ELIGIBLE and confidence to HIGH or MODERATE where the desk correctly holds the cell at `held`/`empty`/`candidate` with confidence not declared. This is not the desk being wrong. It is this engine being too naive to use safely: §4's own text — "count originators, not documents or outlets" — presumes a prior, semantic judgement this engine cannot make from the current schema: *which cited sources actually assert the cell's specific claim*, versus which are cited as context, as a negative/NOT-FOUND result, or as out of the cell's time period. The desk already makes this call by hand (e.g. cell 05's per-source notes mark some citations "different period" or "one event"; cell 06's sources are cited precisely to document that PNH accountability data was *searched for and not found*, not that it was found). That distinction is not a structured field anywhere in either desk file — the free-text per-source notes are a partial, inconsistent hint, not something this engine should parse and act on. Mechanically counting every cited source as a qualifying originator, as done below, systematically inflates eligibility and confidence — exactly the failure mode the whole platform exists to prevent. **Recommendation:** add a structured per-citation field (e.g. `role`: `asserts` / `context` / `out-of-scope` / `negative-result`) before any gate/confidence computation is trusted beyond diagnostic use, and before task "wire engine into desk pages" proceeds. That field is an editorial decision for the desk to make per citation, not something to infer or backfill here.

The mismatches below are shown anyway, in full, because they are the evidence for the finding above — not because they are action items to fix by changing the desk's numbers.

## Known limitations of this engine

0. **Claim-relevance is not a structured field (see Headline finding above).** This is the limitation that actually matters; the rest are secondary until this one is fixed.
1. **No provenance chain yet.** §3 of the master prompt calls for DIRECT/RELAY/DERIVED/SECONDARY/UNRESOLVED per source. Neither desk file has this field. Independence here is judged only from the `o` originator string (Cadre 509, via its `originators` table) or raw `o` text (Cadre 7, no table at all — a real gap: two differently-worded mentions of the same organization will be double-counted as independent). Adding the provenance field and, for Cadre 7, an `originators` table like Cadre 509's, is the next concrete step toward §3.
2. **Confidence formula has no contradiction input from the data.** Cadre 7's N-001 is the clearest case: the desk set confidence to MODERATE for a documented reason (an unpublished bilateral exchange cannot be excluded) that is not a hard contradiction, just residual uncertainty. This engine has no field to read that from, so it computes HIGH and flags a mismatch that is not actually an error — it is the engine missing an input, not the desk being wrong. Recommend adding an explicit `residual_uncertainty` or `soft_discrepancy` flag to the note/cell schema, with a short reason string, before treating this engine's confidence output as more than advisory.
3. **Discrepancies aren't linked to specific cells/notes.** Cadre 509's `discrepancies` array (D-509-xx) has no field tying a discrepancy to the cell(s) it affects, so this engine cannot mechanically treat a logged discrepancy as the "material contradiction" input to §4's confidence rule. It currently assumes no contradiction for every cell, which is optimistic. Worth adding a `cells` or `notes` link array to each discrepancy entry.
4. **This audit does not cover Cadre 22** (`cadre/index.html`, ~6,000 lines, no separate JSON ledger) — its data model needs to be extracted before this engine can run against it.
